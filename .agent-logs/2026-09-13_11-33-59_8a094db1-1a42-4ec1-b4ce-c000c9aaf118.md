Good catch — that's a real, separate bug in `monitorCall`, not something I introduced but worth fixing now since we're in this code. Here's the issue:

`aloneSince` starts counting the moment `count <= 1`, with no memory of whether other people were *ever* in the call. So if the bot joins first and sits alone for 2 minutes waiting for humans to show up, that's currently indistinguishable from "everyone left" — both trip the same `ALONE` reason and the bot walks out before the meeting even started for real.

**The fix:** track whether the bot has ever actually seen another participant (`count > 1`) at some point. Only let the alone-timeout fire once that's true — i.e., "alone" only counts as a leave signal if it's *people left*, not *people haven't arrived yet*. Concretely, in [session.ts](backend/src/session.ts)'s `monitorCall`:

```ts
let previousCount: number | null = null;
let aloneSince: number | null = null;
let hadOthers = false;   // has the bot ever seen someone else in this call?

for (;;) {
  ...
  const count = await getParticipantCount(page);
  if (count !== null && count > 1) hadOthers = true;
  ...
  // Only the "people left" case counts as a leave signal — being alone
  // before anyone has shown up yet is just waiting for the meeting to start.
```
